两条曾失败的用例与其当前结论：

1. `liveStatusFailureDeniesBothCookieAndBearerRequestsAndRecoversWithoutStaleAcceptance` — 断言 503 实际 500。证据：`iam-web/target/independent-rp/crm.log` 22:01:07 `AuthenticationServiceException: Identity state unavailable`，链式原因为 `OAuth2IntrospectionException: 503 ... on POST /oauth/introspect`。拒绝行为正确（fail-closed），是 Spring 默认把该异常映射为 500 导致状态码不合规。修复位置：`LiveAccessDecoder` 将 introspection 故障收敛为 `JwtException("Identity state unavailable")`，`BffStateFilter` 与 `RpSecurity` 显式返回 503。
2. `directoryPasswordChangeInvalidatesBothIndependentRpsAndTheirApiTokens` — 期望 200 实际 400。证据：`iam.log` 22:01:12.315 `MissingRequestHeaderException: Required request header 'Idempotency-Key' ... is not present`。根因在测试夹具：IT 内代理 `forward()` 的转发头白名单原只含 `Authorization/Cookie/Content-Type/Origin`，把 `Idempotency-Key` 与 `X-CSRF-TOKEN` 剥掉（21:59 同一用例先表现为 403，即 CSRF 头被剥的同一来源）。属夹具缺陷而非产品缺陷；修复位置为白名单加入这两个头。修复后 22:02:56 该用例通过，改密请求起点到两个 RP 与 API 全部拒绝的本地观察为 586ms（`revocation-observations.md`，单次串行样本，不是 P99 或五秒 SLA 证据）。

07:56 的 `Invalid client specification` 为注册参数问题：客户端 ID `hr` 只有 2 个字符，未通过 `ClientRegistrationService` 的 `[A-Za-z0-9_.-]{3,100}` 校验。以单文件程序实测：`crm -> true`、`hr -> false`、`hrm -> true`；改用 `hrm` 后启动通过。该约束已写入 `docs/19` 的配置章节。
