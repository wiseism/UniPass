## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T8。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 管理 API 独立权限：APP_ADMIN、USER_OPERATOR、AUDITOR、SYSTEM_ADMIN；业务应用授权继续由业务系统负责。
2. 应用注册校验重定向 URL、客户端类型、scope 和负责人；secret 仅展示一次并存单向校验值，轮换设双密钥有效窗口。
3. 禁用账号先在本地 gate/epoch 阻断访问，再提交目录变更并追踪结果，失败不得自动恢复放行；强制下线必须可审计。
4. 用户重置、密钥操作、外部绑定与 DEAD 重放要求近期 MFA 和具体原因；重放创建可追溯的新尝试，禁止直接改任务终态为成功。
5. 审计记录 actor、subject、action、result、client_id、source_ip、trace_id、operation_id 和时间；按允许字段构建 detail，不直接序列化请求体。
6. 写操作的审计与业务变更同事务保存，归档异步执行；审计失败阻断特权变更。只读查询按游标分页，导出受权限和行数限制。
7. 当前具体管理权限为 `ROLE_ADMIN_PASSWORD_RESET`、`ROLE_ADMIN_PASSWORD_RECOVERY` 与 `ROLE_ADMIN_MFA_RECOVERY`，分别控制密码重置、目录结果证据恢复和丢失因素恢复，不能互相推导。MFA 恢复禁止操作员授权自己；签发、兑换与确认检查实时权限和相关 epoch，原因与核验引用同事务保留，见 [因素生命周期](../18-MFA因素轮换与受控恢复.md)。角色授予和控制台入口仍属 T8 后续实现。

## 3. 数据与契约

audit_log 按时间分区，索引(user_id,created_at)、(trace_id)；归档至少六个月可恢复并保留完整性校验。代理 IP 仅信任登记 LB 的转发头。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

角色越权、IDOR、secret 轮换、审计落库失败、恶意 detail、导出脱敏、管理员重放与恢复操作全链路留痕。

交付物：管理页面、权限矩阵、审计字段字典、归档恢复报告；对应 A7。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
