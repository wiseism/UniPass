# T8 管理控制台与审计查询增量

版本 V1.0（2026-10-23）。本记录承接 [分阶段实施进度](10-阶段实施进度.md) 的 "T8 管理控制台第一期"，属于 T8 的编码增量，不改变 T8 或全项目的验收状态。

## 范围

新增 V13 迁移与 `iam-server` 管理控制台第一版：

- `auth_audit` 扩展 `result`、`client_id`、`source_ip`、`operation_id`、`detail`（jsonb），并补 `(user_id, created_at)` 与 `trace_id` 索引；既有 `AccountState.audit` 调用延续默认值不变。
- `AdminAuditService`：写入方必须在其事务内调用，审计失败即回滚特权变更；detail 键固定白名单（role/reason/login/target_action/replay/operator），未知键、越 500 长度或含控制字符直接拒绝。查询为最新优先、`(created_at,id)` 跨时间戳稳定排序，游标为 Base64url 不透明串（覆盖毫秒时间戳与 UUID tiebreaker），上限 100 条；导出为 CSV，硬上限 1000 行。
- `AdminConsoleService/Controller`：`/api/admin/console/*`。角色授予/撤销仅限固定角色集合（`ROLE_SYSTEM_ADMIN`、`ROLE_ADMIN_PASSWORD_RESET`、`ROLE_ADMIN_PASSWORD_RECOVERY`、`ROLE_ADMIN_MFA_RECOVERY`），要求操作员近期密码与近期 MFA；操作、审计与幂等记录同事务提交。同幂等键重复提交同一上下文保持幂等（不重复审计、不复活已撤销角色），上下文变化返回 409；操作员不能撤销自己的最后一个 SYSTEM_ADMIN 角色（409）。
- `AdminRoleCli`：离线操作员工具按员工号授予/撤销角色并留审计，控制台没有首次授权入口。
- 门户新增 `/portal/admin`：审计列表（含游标加载更多）与角色管理面板；导航仅在 `ROLE_SYSTEM_ADMIN` 下出现，服务端每次请求实时复查角色。审计 detail 仅在页面展示角色/原因/重放标记；`source_ip` 不进入列表与导出。

## 边界与未完成

- 应用/客户端管理 HTTP 与控制台页面、双密钥轮换窗口、AUDITOR/USER_OPERATOR/APP_ADMIN 独立权限拆分仍属 T8 后续。
- 审计归档异步化、六个月恢复演练、按真实 LB 转发头的 `source_ip` 登记尚未实现；本增量只记录 `remoteAddr 为空` 的保守形态。
- `detail.reason` 为操作员自述文本，仅做长度/控制字符约束，不代表可信输入。
- 测试不代表生产验收；T8 交付物中的权限矩阵、审计字段字典与归档恢复报告仍待后续增量产出。

## 测试

- `AdminConsoleIT`（真实嵌入式 PostgreSQL，非内存替代）：非授权访问拒绝、授予同时写角色/幂等/审计、同键重放不重复、同键换上下文 409、契约违规（未知动作/越权角色/空原因/控制字符/目标不存在）零落库、审计插入失败整事务回滚、最后一个管理员自我撤销被拒、审计分页排序/游标长度与解析校验/openapi detail 白名单/导出上限与表头、旧授权键重放不复活已撤销角色。
- 门户 `admin.test.ts`：非操作员零请求拒绝、审计列表游标续读、授予携带 `Idempotency-Key` 与原因、恶意 cursor 客户端校验守卫。
- 全量 Maven 与 Gradle、前端 typecheck/test/build 均在远程 CI 执行，结果见该次 workflow 记录；本文不预填通过结论。

## 操作员入口

```text
# 首份控制台权限只能离线授予（应用主包内 main class）
UNIPASS_DB_URL=... UNIPASS_DB_USER=... UNIPASS_DB_PASSWORD=... \
  java -cp iam-server-0.1.0-SNAPSHOT-exec.jar com.unipass.server.AdminRoleCli grant <employee_no> ROLE_SYSTEM_ADMIN
```

角色变更随后即可在 `/portal/admin` 用固定角色集合完成，全部留痕。
